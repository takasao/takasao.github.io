コード、実データ、認証、生成物は別に扱います。古い PC の `.venv` や `.git` をコピーしません。

## 設定とデータ


追加の共通設定はありません。実際の入力・保存先は各機能の手順で指定します。

端末固有の場所・認証値はローカル設定に置きます。共有された設定をそのまま使う前に、
保存先・実行主体・外部送信範囲を確認してください。Bot や定期ジョブはこの導入手順では起動しません。

## 非破壊の確認

```sh
git status --short
```

成功したら README・Quickstart の通常ワークフローへ進みます。ヘルプや import の成功だけでは、
実データ・外部サービス・GUI の動作確認完了とは扱いません。

## 更新と復旧

1. bootstrap の `bin/sync.sh --refresh` でコードの取得候補を確認します。
2. `--apply` で安全なコードだけを更新します。別ブランチ・dirty・分岐は手動確認です。
3. lockfile が変わった場合だけ上記の環境構築を明示的に行います。
4. 失敗時はエラーを保存し、データと旧環境を保持します。強制 reset や共有環境への無条件 pip install は行いません。

このページは手順を記述したものです。検証実績は対応 PR の Validation を確認してください。
